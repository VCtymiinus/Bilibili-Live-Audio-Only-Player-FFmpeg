bililive v1.3 - 只听哔哩哔哩直播的声音
================================================

【重要】从源码仓库拿到的这份是「不完整」的
--------------------------------------------
仓库里**不含 ffplay.exe**。原因：它单个就有 102 MB，超过 GitHub
单文件 100 MB 的硬限制，根本推不上去。

缺了它就**没法播放**。请选一种方式补上：

1. 从本仓库的 **Releases** 页面下载完整打包版（里面已经带好），或者
2. 用仓库里的脚本自己取一个：

       python probe/fetch_ffmpeg.py      # 下载静态 ffmpeg 包
       python probe/extract_ffplay.py    # 从包里解出 ffplay.exe

   然后把得到的 `ffplay.exe` 放到本文件夹**根目录**（和 bililive.exe 并排）。
   注意：是放在 `bililive-1.3-win64\` 下，不是放进 `_internal\`。
3. 已经有 ffplay 的话，设环境变量指过去也行：
       set BILILIVE_FFPLAY=D:\你的路径\ffplay.exe

放好之后，文件夹里应该是这样：
    bililive.exe     <- 双击这个
    ffplay.exe       <- 必须在这里
    _internal\       <- 运行库，不要动
    使用说明.txt      <- 本文件


界面长什么样
------------
打开后是一个居中的窗口，从上到下：

    +--------------------------------------+
    |  bililive   只听哔哩哔哩直播的声音     |
    |  --------------------------------    |
    |  直播间房间号                         |
    |  +--------------------------------+  |
    |  |           26774400             |  |
    |  +--------------------------------+  |   <- 输入房间号，回车即可开始
    |  地址栏 live.bilibili.com/ 后面...    |
    |                                      |
    |  主播名字                             |   <- 连上后自动出现
    |  直播间标题                           |
    |                                      |
    |  音量                        70%      |
    |  ----------o---------------          |   <- 拖动调音量
    |                                      |
    |  播放中 12.4 分钟                     |   <- 实时状态
    |  [  换到该房间  ]   [ 暂停 ] [缩成悬浮窗] |
    +--------------------------------------+

**主按钮显示的就是「点下去会发生什么」**：
    还没开始          -> [开始收听]
    正在放当前房间    -> [重新连接]      （想重连就点它）
    输入框改成了别的房间 -> [换到该房间]   （点它立刻换台）
    暂停中            -> [继续收听]
    [暂停] 按钮负责暂停 / 继续。

**换房间**：把输入框里的房间号改掉，然后**点那个按钮或按回车**都行 ——
按钮文字会自动从「重新连接」变成「换到该房间」，一眼能看出点它会做什么。
实测换台约 1 秒，主播名和标题都会跟着换。

想停止收听：**关掉窗口**即可（声音会立刻停，不会留后台进程）。
想腾出屏幕：点「缩成悬浮窗」，变成右上角的小方块。

**键盘快捷键**（窗口聚焦时可用）：
    回车        开始收听 / 换到新输入的房间
    空格        暂停 / 继续
    ↑ / ↓       音量 ±5
    Esc         从悬浮窗展开回完整窗口


悬浮窗（右上角的小方块）
------------------------
    +--------------------------------+
    |  bililive  主播名字         [X]|
    |  播放中 12.4 分钟              |
    |  ( ❚❚ )   音量 ---o----  70%   |
    |  [        展开设置          ]  |
    +--------------------------------+

* **按住最上面那条**可以把它拖到任意位置
* 左边方块是**暂停/继续**：❚❚ 表示正在播，点一下变 ▶ 就暂停了
* **拖动音量**滑块，松手后生效
* 点「展开设置」回到完整窗口，点 **✕** 退出程序


这个文件夹不需要装 Python，解压出来就能用

怎么用
------
1. 双击 bililive.exe
2. 在窗口里输入直播间房间号（浏览器地址栏 live.bilibili.com/ 后面那串数字）
3. 按回车（或点「开始收听」），等几秒开始出声

也可以带参数直接跑：
    bililive.exe 26774400            普通启动
    bililive.exe 26774400 --volume 60    音量 60（0-100，默认 100）
    bililive.exe 26774400 --volume 0     静音（只连不响，用于测试）

不想用界面、只要命令行：
    bililive.exe 26774400 --no-gui
想强制显示界面：
    bililive.exe 26774400 --gui

停止播放：关掉窗口。声音会立刻停。

**这个文件夹里各是什么**
    bililive.exe    主程序（约 1.4 MB）
    ffplay.exe      播放器（约 102 MB，必须和 bililive.exe 放在一起）
    _internal\      运行需要的库文件，**不要删、不要单独搬走**
    使用说明.txt     本文件

请**整个文件夹一起拷**，单独把 bililive.exe 拿出来会缺库跑不起来。

**首次运行可能出现「Windows 已保护你的电脑」**
那是因为这个程序**没有数字签名**（个人做的小工具都不会有）。
点「更多信息」→「仍要运行」即可。这**不是杀毒软件报毒** ——
没有任何安全软件把它判成病毒，只是不认识这个发布者。

查看版本：bililive.exe --version


暂停和音量：两件必须如实说明的事
--------------------------------
**一、暂停再继续，暂停期间的内容会跳过。**

    直播是实时的，主播不会因为你按了暂停就停下来。所以本工具里的
    「暂停」实际是「先不响了」，「继续」是**从当下接着听**——
    不会把暂停期间落下的内容补播一遍。
    恢复出声需要重新连接，实测约 2.6 秒。

**二、调音量会短暂断一下音（约 1~3 秒）。**

    原因：ffplay 这个播放器不支持播放中改音量，只能在启动时指定。
    所以拖完音量滑块后，本工具会用它**重新启动一次播放**来套用新音量，
    这一下会有 1~3 秒没声音。

    为什么不用更顺滑的办法？为了守住一条底线：
    **只调这个工具的音量，不把微信、浏览器一起调小。**
    采样系统总音量的做法会连带改掉整个系统，毁掉本工具
    「不影响其他程序」的性质，所以没有采用。

    如果你希望**调音量时一点都不断音**：右键任务栏喇叭图标 ->
    打开音量合成器 -> 找到 ffplay.exe 那一格单独拖动。
    这样同样只影响本工具，而且即时生效、完全不断音。


需要什么
--------
* 64 位 Windows
* **什么都不用装** —— 这个文件夹自带 Python 运行时和 ffplay.exe
* 不需要管理员权限

（想用源码版而不是打包版，才需要自己装 Python 3.8+ 并用 start.bat 启动。）

这个文件夹可以搬走
------------------
ffplay.exe 是静态自包含的，整个文件夹（含 _internal\）压缩后可以拷到任何
64 位 Windows 上直接用，**目标机器不需要装 Python 或 ffmpeg**。
所有路径都相对于本文件夹，不依赖任何绝对路径、不写注册表。


它省多少流量
------------
实测同一个房间：

    只听声音      150 kbps    65 MB/小时    1.5 GB/天
    看直播画面    692 kbps   297 MB/小时    7.0 GB/天

省约 78%。而且这条纯音频流里视频数据是一个字节都没传
（实测 video tag = 0），不是"传了不用"。

**这个数字的局限如实说明**：来自单次 10 秒抽样的两点外推，
样本很小；692 kbps 是 B 站默认档位，不是你平时实际观看的档位。
方向（纯音频确实省得多）是可靠的，具体倍数会随房间和画质变化。
想自己复现或重测，见开发目录下的 probe/measure_traffic.py。


音量怎么调
----------
三种办法，按方便程度排：

1. **悬浮窗上拖滑块**（v1.3 起）。松手后生效，会有一次 1~3 秒断音，
   原因见上面「暂停和音量」那一节。
2. **启动时指定**：bililive.exe <房间号> --volume <0-100>
3. **完全不断音的办法**：右键任务栏喇叭图标 -> 打开音量合成器 ->
   找到 ffplay.exe 单独拖动。这样也只影响这个工具，
   不会把微信、浏览器一起调小，而且即时生效。

注意 100 就是上限，填 150 也只会是 100（ffplay 自身限制，
超范围会被夹紧，不是放大）。


主播没开播会怎样
----------------
不会报错退出，而是挂着等：

    该直播间当前没有开播（live_status=2）。
    工具会每 30 秒自动检查一次，一开播就会开始播放。

适合提前挂着等主播开播。想退出就关窗口。
房间号打错则会直接退出，不会无限重试。


稳定性设计
----------
* 音频地址约 1 小时过期 -> 提前 10 分钟主动换新
* 一次接口拿 12 条跨 CDN 候选 -> 当前一条失败会自动换下一条
* ffplay 异常退出 -> 指数退避重连（2s 起，60s 封顶）
* 关掉窗口 -> Job Object 保证 ffplay 一起终止，不会留下继续放音
* 暂停/继续、调音量都是**改状态位**，真正的活由后台播放线程干，
  所以按按钮不会把窗口卡住


已知限制（请如实了解）
----------------------
* 依赖 B 站的私有接口，属于逆向实现。官方改协议就得跟着改。
* 音频地址续期时会重启播放，有约 0.3~1 秒断音。听人说话基本无感。
* 暂停后继续是从**当下**接着听，暂停期间的内容会跳过（原因见上）。
* 调音量也会有一次 1~3 秒断音（原因见上）。
* 不登录只能拿默认音质档位。
* **关闭了 ffplay 的 TLS 证书校验**。原因是 B 站 CDN 的证书链用
  gnutls 校验会失败（实测报 "Peer certificate failed verification"）。
  代价要说清楚：关掉校验等于放弃验证服务器身份，理论上中间人可以
  替换音频内容。本工具只听公开直播的声音、不传任何凭据，
  风险可以接受；但它确实是一个真实的降级，不是小毛病。
  想更稳妥可以换用带 openssl 后端的 ffmpeg 构建。
